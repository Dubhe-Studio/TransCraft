# 界面多语言（i18n）说明

界面语言决定界面自身用哪门语言渲染，与页面上展示的翻译数据无关。本文说明它的实现位置、运行时行为，以及新增一种界面语言的完整步骤。

## 一、先分清两个「语言」

顶栏有两个语言入口，含义完全不同，存储键也只差一个词，改动时不要混用：

| 概念 | 存储键 | 代码位置 | 作用 |
| --- | --- | --- | --- |
| 界面语言 | `transcraft_i18n`（JSON，字段 `locale`） | `src/i18n/index.ts` 的 `useLocaleStore` | 决定界面文案，当前取值 `zh`、`en` |
| 翻译工作语言 | `transcraft_ui`（JSON，字段 `currentLanguage`） | `src/stores/ui.ts` 的 `currentLanguage` | 决定仪表盘、项目详情、翻译页取哪门语言的数据，取值来自后端 `supportedLanguages` |

界面语言是界面维度，翻译工作语言是内容维度，两者互不联动。

## 二、相关文件

| 文件 | 职责 |
| --- | --- |
| `src/locale/zh.json`、`src/locale/en.json` | 各语言的界面文案。跨页面共用的词放在 `common`、`member`、`slug`、`project`、`part`、`language_progress` 等共享分组，标签页标题放在 `route`，页面与组件文案放在同名分组（如 `project_detail`、`part_translate`） |
| `src/locale/index.ts` | 把语言包聚合成 `messages`，并由 `keyof typeof messages` 导出 `LocaleCode` |
| `src/i18n/index.ts` | 创建 vue-i18n 实例；`localeTable` 维护语言代码、显示名与 BCP 47 标签；`useLocaleStore` 保存当前语言；启动与切换时同步 `html lang` 与 Arco 组件文案 |
| `src/router/index.ts` | 路由表与守卫；标签页标题按 `meta.titleKey` 与当前界面语言渲染 |
| `src/layouts/MainLayout.vue` | 顶栏语言菜单：显示当前语言，悬停列出全部语言，点选切换 |
| `src/components/AuthLocaleMenu.vue` | 登录页与注册页右上角的语言入口，两页共用 |
| `src/main.ts` | 注册 pinia 持久化插件，挂载前创建 `useLocaleStore` 恢复界面语言；`app.use(i18n)` 使组件模板里的 `$t` 可用 |

文案分组以使用位置为准：`common` 放与具体页面无关、被多处共用的词（「重试」「取消」「列表分隔符」「加载语言列表失败」）；跨页面共用的领域概念单独成组，例如 `member`（三处成员表格）、`slug`（项目与部件的地址标识说明）、`project` 与 `part`（两类实体的字段名）；`route` 专门放浏览器标签页标题；只用在一处的文案放进它所属的页面或组件分组，不要让一个页面分组去引用另一个页面分组的键。

## 三、运行时行为

界面语言由 `useLocaleStore` 保存，持久化交给 `pinia-plugin-persistedstate`（`persist.key` 为 `transcraft_i18n`，`pick` 只含 `locale`）。

启动时 `main.ts` 在 `mount` 之前创建一次 `useLocaleStore` 并调用 `initLocale()`：它先校验持久化恢复的语言，再写入 vue-i18n、`html lang` 与 Arco 文案，因此首帧渲染前界面语言已经生效。这里刻意不用 `persist.afterHydrate`——反序列化失败时插件会跳过该钩子，界面语言就只剩 vue-i18n 生效，`html lang` 与 Arco 文案会停在旧值。没有可用的本地记录时按浏览器语言确定。

本地记录属不可信输入：反序列化失败或取值不在语言表里时，`initLocale` 都会回落到浏览器语言；校验用 `Object.hasOwn`，`constructor` 这类原型链属性名不会命中。插件已开启 `debug`，本地记录损坏会在控制台报错，不会被静默吞掉。

存储键与旧版直接存裸字符串的 `transcraft_locale` 不同，旧记录不再读取，界面语言会一次性重置为浏览器语言。

`useLocaleStore()` 对外提供五项内容：`locale`（当前语言代码）、`current`（当前语言的完整选项，含 `label` 与 `bcp47`）、`locales`（按语言表顺序排列的全部语言）、`setLocale(code)`（切换语言）、`initLocale()`（启动时校验并应用持久化恢复的语言，只应由 `main.ts` 在挂载前调用一次）。

切换走 `setLocale`，它一次完成三件事：更新 store 与 vue-i18n 的 locale、写 `html lang`、切换 Arco 组件内置文案（弹窗按钮、分页、日期选择器等）。写入本地由持久化插件在状态变化后自动完成，不要再手动读写存储键。

语言包缺条目时按 `fallbackLocale: 'en'` 回落到英文，vue-i18n 同时会打印缺失告警。回落方向是英文，所以中文语言包里漏掉某个键时，中文界面会显示英文文案。

## 四、新增一种界面语言

以日语（`ja`）为例。

### 1. 新建语言包

新建 `src/locale/ja.json`，键与 `zh.json` 保持一致。

### 2. 注册语言包

`src/locale/index.ts`：

```ts
import en from './en.json'
import ja from './ja.json'
import zh from './zh.json'

export const messages = { zh, en, ja }

export type LocaleCode = keyof typeof messages
```

`LocaleCode` 由 `messages` 的键推导，这里加完，`LocaleCode` 自动包含 `ja`。

### 3. 补界面语言表

`src/i18n/index.ts` 的 `localeTable`：

```ts
const localeTable: Record<LocaleCode, LocaleMeta> = {
  zh: { label: '简体中文', bcp47: 'zh-CN' },
  en: { label: 'English', bcp47: 'en-US' },
  ja: { label: '日本語', bcp47: 'ja-JP' },
}
```

`label` 是菜单中显示的语言名，用该语言自身书写；`bcp47` 同时用于 `html lang` 与 Arco 语言包代码。字段类型是 `Record<LocaleCode, LocaleMeta>`，漏写一项会直接编译报错。

### 4. 注册 Arco 语言包

Arco 组件的内置文案不走 vue-i18n，且 Arco 默认只注册了 `zh-CN`，因此必须在 `src/i18n/index.ts` 里显式注册：

```ts
import arcoJaJP from '@arco-design/web-vue/es/locale/lang/ja-jp'

addI18nMessages({
  'zh-CN': arcoZhCN,
  'en-US': arcoEnUS,
  'ja-JP': arcoJaJP,
})
```

漏掉这一步不会编译报错，但 `useLocale('ja-JP')` 只会在控制台警告并保持旧语言，表现为弹窗按钮、分页、日期选择器仍是中/英文。Arco 2.58 自带 `ar-eg`、`de-de`、`en-us`、`es-es`、`fr-fr`、`id-id`、`it-it`、`ja-jp`、`km-kh`、`ko-kr`、`ms-my`、`nl-nl`、`pt-pt`、`ru-ru`、`th-th`、`vi-vn`、`zh-cn`、`zh-tw`。

### 5. 浏览器语言探测

`detectLocale` 按 `navigator.languages`（浏览器给出的有序偏好表）从前往后匹配，取第一个能命中的界面语言；比对时只取语言标签的主语言子标签，因此 `en-GB` 命中 `en`、`zh-Hant-TW` 命中 `zh`。它只负责「没有可用本地记录时用什么」，本地记录的有效性由 `pickLocale` 判断：

```ts
function detectLocale(): LocaleCode {
  for (const tag of navigator.languages) {
    const matched = locales.find((item) => item.code === tag.split('-')[0].toLowerCase())
    if (matched) {
      return matched.code
    }
  }
  return 'en'
}

function pickLocale(value: unknown): LocaleCode {
  return typeof value === 'string' && Object.hasOwn(localeTable, value) ? (value as LocaleCode) : detectLocale()
}
```

新增语言时这里不用改，只要语言表的 `code` 与主语言子标签一致（例如 `ja` 对应 `ja-JP`、`ja` 等标签）。末尾的 `'en'` 是偏好表里一项都匹配不上时的落点，可以按需要改成别的语言。匹配只看主语言子标签，因此将来若同一门语言要区分多个语言包（例如简体 `zh` 与繁体 `zh-TW`），需要在这里补一条更具体的比对规则。

### 6. 不需要动的地方

顶栏菜单遍历的是 `localeStore.locales`，新语言会自动出现在列表里，顺序即 `localeTable` 的书写顺序。老用户也无需迁移：本地记录里认不出的代码会被忽略，自动回落到浏览器语言。

## 五、文案的维护与注意事项

模板里用 `$t('key')`（`main.ts` 里的 `app.use(i18n)` 配合 `globalInjection: true`），`<script setup>` 里用 vue-i18n 的 `useI18n()` 取 `t`；两者都会随语言切换自动重渲染。

**标签页标题。** 路由的 `meta.titleKey` 存的是 `route` 分组的键（如 `route.project_detail`），`router/index.ts` 在 `afterEach` 里按当前语言渲染成 `页面名 · TransCraft`，并额外监听 `i18n.global.locale`：切换语言不触发导航，没有这个监听时标题会停在旧语言。站点名 `TransCraft` 不翻译，只作为常量出现在拼接处。

语言包之间目前没有键一致性的编译期检查，缺的键会回落到英文。想让「缺键」在编译期暴露，可以在 `src/locale/index.ts` 里给其它语言包标注中文语言包的类型（`const ja: typeof zh = jaJson`）；注意这拦不住多出来的键。

日期与数字不会自动跟随界面语言，也不能依赖无参 `toLocale*` 的默认值——那取的是浏览器区域设置，可能与界面语言不一致。统一走 `src/format.ts` 的 `formatDate(value, locale)` 与 `formatNumber(value, locale)`，调用方传 `useLocaleStore().current.bcp47`：项目列表与管理后台的时间列用前者，进度表计数、语言进度摘要用后者。新增日期或数字展示时照此处理，或改用 vue-i18n 的 `d()` 与 `n()`。

文案迁移已经完成：全部页面、共用组件、`Message` 提示、`Modal` 确认框与标签页标题都从语言包取词，`zh.json` 与 `en.json` 的键完全对齐（当前各 337 个键，含嵌套分组）。`console.error` 的日志仍是中文，因为它们面向开发者而不是界面；`api/client.ts` 在响应体里取不到 `message` 时使用的兜底错误 `请求失败（HTTP 状态码）` 同样是中文，它属于接口层，未接入界面语言（原因见 `docs/frontend.md` 第十五节）。新增页面时按上面的分组约定补语言包，并保证 `zh` 与 `en` 的键齐全——漏键不会编译报错，只会按上一节所述静默回落到英文。

改动后跑一次类型检查（`vue-tsc`），再手动切换一遍语言，确认界面文案、`html lang` 与 Arco 组件内置文案三者一致。
